# CVB-012 — Create the NestJS API Application

## Type

Technical Task

## Priority

P0

## Story Points

3

## Goal

Initialize the backend API inside `apps/api` using NestJS and TypeScript.

The application must integrate with the existing npm workspace, Turborepo, shared TypeScript configuration, shared ESLint configuration, and root lockfile.

## Scope

Create and configure:

* NestJS application in `apps/api`
* TypeScript strict mode
* Environment-variable validation
* Global API prefix
* Global request validation
* Health-check endpoint
* Swagger documentation for non-production environments
* Structured application configuration
* Graceful shutdown
* Workspace scripts
* Initial API tests

## Technical Requirements

* Use NestJS.
* Use the Fastify adapter unless a concrete compatibility issue requires Express.
* Use strict TypeScript.
* Extend the root TypeScript configuration.
* Use npm workspaces.
* Do not create a separate lockfile inside `apps/api`.
* Use the shared ESLint configuration.
* Use NestJS configuration facilities with typed environment validation.
* Use class-validator and class-transformer for request validation.
* Configure graceful shutdown hooks.
* Keep the application minimal and framework-focused.
* Do not add database, authentication, Redis, BullMQ, Docker, or CV features.

```text
├── src/

├── test/

├── tsconfig.json

```

Codex may adjust test tooling or file names when required by the selected NestJS version while preserving the required behavior.

## Required Workspace Scripts

The `apps/api/package.json` must provide:

```json
{
  "scripts": {
    "dev": "nest start --watch",
    "build": "nest build",
    "start": "node dist/main.js",
    "lint": "eslint .",
    "typecheck": "tsc --noEmit",
    "test": "vitest run",
    "test:e2e": "vitest run --config vitest.e2e.config.ts"
  }
}
```

Script details may be adjusted for compatibility, but all capabilities must remain available.

## API Prefix

Configure the global API prefix:

```text
/api
```

## Health Endpoint

Create:

```text
GET /api/health
```

Expected successful response:

```json
{
  "status": "ok",
  "service": "api"
}
```

The endpoint must return HTTP status `200`.

## Global Validation

Configure a global validation pipe with:

* `whitelist: true`
* `forbidNonWhitelisted: true`
* `transform: true`

The application should reject unexpected request properties when DTOs are introduced.

## Environment Validation

Create typed environment validation.

Supported variables should include at least:

```text
NODE_ENV
API_PORT
API_HOST
CORS_ORIGINS
SWAGGER_ENABLED
```

Requirements:

* Provide safe development defaults where appropriate.
* Fail clearly when invalid values are supplied.
* Parse numeric and boolean values correctly.
* Parse multiple CORS origins safely.
* Do not commit secrets.
* Add or update `.env.example`.

## CORS

Configure CORS using the validated environment configuration.

Requirements:

* Development origin should be configurable.
* Do not allow all origins unconditionally in production.
* Credentials behavior must be explicit.
* Invalid origin configuration must fail clearly.

## Swagger

Expose Swagger only when enabled through configuration.

Suggested route:

```text
/api/docs
```

Requirements:

* Swagger is enabled by default only outside production or through an explicit setting.
* API title and version are configured.
* Swagger must not expose secrets.
* Swagger availability must be testable.

## Graceful Shutdown

The application must:

* Enable NestJS shutdown hooks.
* Close cleanly on termination signals.
* Avoid leaving the HTTP server running after shutdown.
* Be suitable for future Docker deployment.

## Testing Requirements

Add tests for at least:

* Health controller or service
* Health endpoint response
* Health endpoint HTTP status
* Environment validation
* Application bootstrap behavior where practical

Testing may use Vitest or Jest, but should remain consistent and well integrated with the monorepo.

## Out of Scope

Do not implement:

* PostgreSQL
* Prisma
* Redis
* BullMQ
* Worker application
* Dockerfiles
* Docker Compose
* Authentication
* Authorization
* User accounts
* CV APIs
* File uploads
* Object storage
* PDF generation
* AI features
* Billing
