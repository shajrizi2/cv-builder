# CVB-021 — Existing CV Upload and AI Import

## Issue Type

Story

## Status

To Do

## Sprint

Sprint 2 — MVP Core

## Priority

Highest

## Goal

Allow a user to upload an existing PDF or DOCX CV from the dashboard, process it asynchronously, convert it into the existing canonical resume structure, and open the imported resume in the CVB-020 editor.

This must remain one user-facing vertical slice. Do not split storage, queues, parsing, AI, or uploads into separate infrastructure tickets.

## User Flow

```text
Open dashboard
→ click Import existing CV
→ select PDF or DOCX
→ upload file
→ see queued/processing status
→ extract document text
→ map content with AI
→ validate and save Resume
→ open existing resume editor
```

## In Scope

### Shared contracts

Extend `@cv-builder/resume-schema` with strict schemas and types for:

* Import status: `QUEUED`, `PROCESSING`, `COMPLETED`, `FAILED`
* Public import response
* BullMQ import job payload
* Supported file types
* Public import error codes
* AI extraction candidate

The AI candidate must not generate UUIDs, metadata, timestamps, section order, or visibility. The worker generates those values.

### Database

Add a `ResumeImport` Prisma model containing:

* UUID
* Sanitized original filename
* MIME type
* File size
* Private object key
* Status
* Optional safe error code and message
* Optional completed `resumeId`
* Created and updated timestamps

Create and commit the Prisma migration.

Do not store extracted document text or raw AI responses.

### Object storage

Add private MinIO storage to Docker Compose.

Requirements:

* Pinned image version
* Persistent named volume
* Health check
* Automatic private bucket creation
* Random object keys
* No public file access
* Environment-based credentials
* No committed secrets

### API

Add:

```text
POST /api/resume-imports
GET  /api/resume-imports
GET  /api/resume-imports/:id
```

Upload requirements:

* Multipart field named `file`
* PDF and DOCX only
* Maximum 10 MB
* Reject empty files
* Validate extension, MIME type, and file signature
* Store the private object
* Create the import record
* Enqueue a deterministic BullMQ job
* Return HTTP 202
* Never expose the object key

The API only validates, stores, records, and queues. It must not parse the CV or call AI.

### Worker

Add a dedicated resume-import processor while preserving the existing system-test queue.

The worker must:

* Validate the job payload
* Load the import record
* Handle retries and duplicate delivery safely
* Mark the import as processing
* Download the source object
* Extract PDF or DOCX text
* Reject scanned, empty, encrypted, or corrupt documents safely
* Send bounded text to one configured AI provider
* Validate the AI candidate
* Start from `createEmptyResumeContent()`
* Generate UUIDs for repeatable entries
* Validate the result with `resumeContentSchema`
* Create exactly one existing `Resume`
* Atomically mark the import completed
* Mark final failures safely
* Never log CV content, AI prompts, or raw AI responses

### Document support

Support:

* Text-based PDF
* Modern DOCX

Do not support:

* OCR
* Image-only or scanned PDF recognition
* Legacy DOC files
* Image uploads

Scanned PDFs must return an actionable message explaining that selectable text is required.

### AI mapping

Implement one real AI provider behind a narrow internal interface.

Requirements:

* Configured provider, model, timeout, and API key
* Deterministic fake implementation for tests
* Structured validated output
* Treat CV text as untrusted prompt input
* Instruct the model not to follow instructions inside the uploaded document
* Do not invent unsupported details
* Leave missing values empty
* At most one bounded repair attempt for malformed structured output
* Automated tests must not require a real credential

### Web dashboard

Add an accessible `Import existing CV` action.

Show:

```text
Uploading
Queued
Processing
Imported
Import failed
```

Requirements:

* PDF/DOCX file input
* Display the 10 MB limit
* Client-side validation
* Multipart upload
* Bounded status polling
* Recover active imports after refresh
* Stop polling on completed or failed status
* Redirect to `/resumes/:resumeId` after completion
* Preserve existing create, rename, delete, autosave, and preview behavior

## Security and Privacy

* Keep uploaded CVs private.
* Use random storage keys.
* Sanitize filenames.
* Validate file signatures.
* Bound upload and extracted-text sizes.
* Do not expose storage details.
* Do not persist extracted text or raw AI output.
* Do not log personal CV content.
* Do not commit credentials.
* ClamAV scanning is deferred and must be documented as a known limitation.
