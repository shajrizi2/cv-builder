# CVB-011 — Create the Next.js Web Application

## Type

Technical Task

## Priority

P0

## Story Points

3

## Goal

Initialize the frontend application inside `apps/web` using Next.js, TypeScript, Tailwind CSS, and the App Router.

The application must integrate correctly with the existing npm workspace and Turborepo configuration.

## Scope

Create and configure:

* Next.js application in `apps/web`
* TypeScript
* App Router
* Tailwind CSS
* ESLint using the shared configuration
* Environment-variable validation
* Basic application layout
* Basic home page
* Health-check endpoint
* Workspace scripts
* Docker-ready Next.js standalone output
* Initial frontend tests

## Technical Requirements

* Use Next.js with the App Router.
* Use TypeScript strict mode.
* Use React.
* Use Tailwind CSS.
* Use the existing root TypeScript configuration.
* Extend the shared ESLint configuration where practical.
* Configure Next.js standalone output for future Docker use.
* Use npm workspaces.
* Do not create a separate lockfile inside `apps/web`.
* Do not install ShadCN components yet unless initialization is required without adding product UI.
* Validate environment variables through a typed configuration module.
* Keep the application minimal and framework-focused.
* Use accessible semantic HTML.
* Do not add authentication or CV features.

## Expected Structure

```text
apps/web/
├── app/
│   ├── api/
│   │   └── health/
│   │       └── route.ts
│   ├── globals.css
│   ├── layout.tsx
│   └── page.tsx
├── lib/
│   └── env.ts
├── public/
├── tests/
├── eslint.config.mjs
├── next.config.ts
├── package.json
├── postcss.config.mjs
├── tsconfig.json
└── vitest.config.ts
```

Codex may adjust file names when required by the installed Next.js or Tailwind versions, while preserving the same functionality.

## Required Workspace Scripts

The `apps/web/package.json` must provide:

```json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "eslint .",
    "typecheck": "tsc --noEmit",
    "test": "vitest run"
  }
}
```

Script details may be adjusted for compatibility, but all capabilities must remain available.

## Health Endpoint

Create:

```text
GET /api/health
```

Expected successful response:

```json
{
  "status": "ok",
  "service": "web"
}
```

The endpoint should return HTTP status `200`.

## Home Page

Create a minimal placeholder page displaying:

* Project name
* Short description
* Confirmation that the frontend application is running

Do not build the final landing page in this ticket.

## Environment Validation

Create a typed environment module.

Requirements:

* Separate public and server-only environment variables.
* Do not expose server-only values to the browser.
* Fail clearly when required values are missing.
* Keep required variables minimal for this ticket.
* Add or update `.env.example` when needed.

## Testing Requirements

Add tests for at least:

* The health-check response
* The basic home-page rendering or a minimal frontend component

Use a testing setup compatible with Next.js and the monorepo.

## Out of Scope

Do not implement:

* NestJS API
* Background worker
* Dockerfiles
* Docker Compose
* Authentication
* Database
* Prisma
* CV editor
* File upload
* PDF generation
* Document parsing
* Billing
* AI features
* Final visual design
